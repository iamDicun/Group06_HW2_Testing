# AI Critique

Trong quá trình thực hiện bài tập này, em nhận thấy AI có nhiều điểm yếu khi tạo test cases cho API testing. Thứ nhất, AI thường đưa ra các khẳng định về mã trạng thái dựa trên quy ước RESTful phổ biến thay vì kiểm tra triển khai thực tế của server — ví dụ như kỳ vọng 201 khi tạo resource, 204 khi xóa, hay 409 khi trùng lặp, trong khi server thực tế trả về 200 cho tất cả các trường hợp này. Thứ hai, AI không xử lý nhất quán việc sử dụng biến môi trường trong collection — nhiều request FR-08 Checkout sử dụng token cứng `Bearer <token>` thay vì biến `{{userToken}}` động, gây ra lỗi collection mà không phải lỗi server. Thứ ba, các test case chuyển đổi trạng thái (như kiểm tra khóa tài khoản) không tính đến việc rò rỉ trạng thái giữa các test — do lỗi `login_attempts + 2` trong server, các test sau bị ảnh hưởng bởi test trước. Thứ tư, AI thiếu các test case edge cases quan trọng như kiểm tra Concurrent checkout, Race condition khi tạo category trùng tên, và Unicode/emoji trong tên category. Nguyên nhân chính là AI làm việc từ đặc tả API chứ không đọc mã nguồn, nên không thể biết được các lỗi như secret key hardcode, JWT không có thời hạn, hay SQL injection. Bài học quan trọng nhất khi hợp tác với AI là: AI rất giỏi trong việc tạo số lượng và cấu trúc test cases một cách nhanh chóng, nhưng con người phải luôn chạy test thực tế, so sánh expected vs actual, và phân biệt giữa lỗi server thật và lỗi thiết kế test. AI cần con người để validate và interpret kết quả.
