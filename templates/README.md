# Template Decision For HW02

The Excel templates are the most complete references for required fields, but the course policy requires text-based submissions and recommends Markdown.

Use this rule for the repo:

| Artifact | Source Of Required Fields | Working Format In Repo |
|----------|---------------------------|------------------------|
| Test case | `KCPM-Week02-Test Cases-Template.xlsx` | Markdown file under `tests/test-cases/` |
| Bug report | `KCPM-Week02-Bug Report-Template.xlsx` and `.github/ISSUE_TEMPLATE/bug-report.yml` | GitHub Issue plus Markdown copy under `submission/bug_reports/` |
| Test run | `test-run-template.md` plus lecture slides | Markdown file under `tests/test-runs/` |
| AI audit | `[AI-02]` template and syllabus | `submission/ai_audit.md` |

Markdown templates should not be treated as simplified final evidence. When a field exists in the Excel template but not in the Markdown template, include it in the Markdown artifact if it is relevant to grading or traceability.

Minimum fields to keep for test cases:

- Test Case ID.
- Test type.
- Requirement name / ID.
- Build or release.
- Objective.
- Preconditions.
- Test steps.
- Test data.
- Expected result.
- Created by.
- AI generated / reviewed status.
- Actual result.
- Status.
- Bug ID.
- Tester.
- Tested date.
- Remark.

Minimum fields to keep for bug reports:

- Bug ID.
- Status.
- Requirement name / ID.
- Summary.
- Steps to reproduce.
- Severity.
- Frequency.
- Priority.
- Attachment / evidence link.
- Date.
- Reporter.
- Build.
